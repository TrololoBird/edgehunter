# Общие правила, которые меняют все стратегии

Код `f386ec3`, проверка 2026-10-16. Этот документ дополняет [20 разборов](STRATEGIES.md). Обнаружение паттерна ещё не определяет торговую систему: проверялся путь detector → `Strategy.plan` → `base_plan`/geometry → `SignalBook._plan/_try_entry/_enter/_manage_trade` → executor. Числа ниже — текущие defaults, а не настройки неизвестного VPS.

## Подтверждённые дополнительные расхождения

Номера S не заменяют старые A01–A18 в [техническом отчёте](REPORT.md). Они относятся к этому проходу сравнения стратегий. Авторская модификация сама по себе не названа программной ошибкой. Приоритет P1 означает изменение входа, риска или выхода действующей стратегии; P2 — более ограниченный эффект, теневой путь или неоднозначная спецификация.

| ID | Тип / приоритет | Код, наблюдение и следствие |
|---|---|---|
| S01 | Единицы данных, P1 | [zones.vwap](../../zones.py): в Σ(P×V)/ΣV подставлен **quote turnover**, хотя V уже содержит цену. Две сделки по одной единице актива за 100 и 200 дают 166.667 вместо 150. Для одноценовых баров здесь нет погрешности typical price: это исключительно неверные веса. Та же формула есть в ORB-теге. Меняются anchored VWAP и цели/контекст; денежный RVOL/OBV автоматически ошибкой не объявляются. Эталон F1. |
| S02 | Цена отсчёта стопа, P1 | [BreakoutStrategy.plan](../../strategies/breakout.py): SL = channel − direction×2N; фактический вход по текущей котировке. При channel=100, N=5, entry=110 SL=90 означает 4N вместо 2N от fill по T1. Даже верный N не исправляет эту ошибку. |
| S03 | Историческая хронология, P1 | [turtle._last_s1_was_winner](../../strategies/turtle.py): `ns[i]` использует полный TR дня, внутри которого был исторический intraday breakout. Этот TR в момент пробоя ещё неизвестен. Открытая гипотетическая сделка объявляется выигравшей по последнему close; T1 определяет исход через неблагоприятные 2N и прибыльный 10-day exit. Это дефект реконструкции фильтра S1, а не утверждение, что live detector читает будущую свечу. На daily OHLC также невозможно установить порядок двух пересечений в одном дне. Проверка статическая, отдельный численный пример не заявляется. |
| S04 | Несогласованные таймфреймы, P1 | [levels.pullback_spread_ok](../../levels.py): сравнение 15m spread с range spring делённым на 2 осталось от 1h. Сам spring уже 4h. В **собственной** sqrt(time) модели нужно деление на 4. Range теста 2 при spring range 8 проходит порог 2.4, хотя согласованный с этой моделью порог 1.2. Это не утверждение, что Wyckoff предписал sqrt(time) или число 0.6. |
| S05 | Проверка RR/score, P1 | [SupplyDemandStrategy.plan](../../strategies/maniac_strategies.py) безусловно добавляет 2 балла за RR до его расчёта. В geometry минимальные 3R проверяются по blended, а не по первой встречной зоне. Реальный план score=10, demand 95..100, supply 102/130, entry=100 допускается с TP1≈0.264R и blend≈3.419R. Это нарушает собственное обещание 3:1 profit zone; D2 прямо выделяет исходную зону прибыли до T1 и количественное 3:1 условие, но не подтверждает нашу формулу score. |
| S06 | Порядок проверки RR, P1 | [BollingerStrategy.plan](../../strategies/maniac_strategies.py) сравнивает target с ещё не расширенным стопом. Trail-ветка [system_levels](../../strategies/geometry.py) после padding/floor не применяет class `min_rr=1` повторно при общем TP1 floor=0. При entry=100, bareSL=99, band=102, native ATR=5 итоговый SL=95, net RR≈0.364, `low_rr=False`. Ошибка собственного ограничения; у Bollinger нет универсального обязательного RR=1. |
| S07 | Потеря максимального риска, P1 | [CupHandleStrategy.plan](../../strategies/cup_handle.py) ограничивает стоп 8% от signal close, затем общий floor расширяет его. При entry=100 и ATR=12 запрошенный SL=92 становится 88. Кроме того, signal close не гарантированно равен fill. N3 ограничивает потерю относительно purchase price; текущая цепочка этого не обеспечивает. |
| S08 | Утраченный признак паттерна, P2 | [cup_handle](../../strategies/cup_handle.py) удалил различение U/V с доводом об отсутствии авторской числовой формулы. Линейное падение и рост по 18 дней с ручкой проходит detector. K1 прямо описывает rounded turn. Отсутствие универсального числового порога не делает свойство необязательным. |
| S09 | Название процентной меры, P2 | [dump_bounce](../../strategies/pump.py) использует base/current−1 ≥ 15%, что соответствует обычному падению 13.0435%. Research P1 использует ту же обратную меру: воспроизведение не показывает ошибку переноса research, а показывает неверное прочтение подписи «−15%». |
| S10 | Нарушение флага выхода, P2 | [SignalBook._manage_trade](../../signal_book.py) проверяет TP1–TP3 даже при `no_tp=True`. Воспроизведён карточный выход TP3 при обоих флагах no_tp/no_stop. В реальных планах target-less систем стоят далёкие служебные цели: пример устанавливает семантику флага, **не** частоту такого события и не исполнение TP на бирже. Executor TP-ордера при этом флаге не создаёт. |
| S11 | Потеря собственной цели, P1 | [WyckoffRangeStrategy.plan](../../strategies/wyckoff_range.py) включает P&F в первоначальные targets, но не сохраняет в `fillers`. При совпадении P&F с ценой LTF-уровня `entry_levels` удаляет его как младший уровень. Пример: 110/140/140 превращается в 109.669/109.669/109.669, P&F 140 пропадает. Фильтр должен различать происхождение целей, а не только совпадение цены. |

Десять численных примеров S01/S02/S04–S11 используют настоящие функции проекта: [скрипт](strategy_reproductions.py), [полный вывод](strategy_reproductions.txt). Это диагностические контрпримеры, не новые тесты торговой стратегии и не backtest доходности.

## Реально действующие настройки и подтверждения

| Обещание / настройка | Что происходит в текущем пути |
|---|---|
| `touch` = resting limit | `executor.touch_confirm_close=True`: ждём касания и закрытия обратно за proximal, затем вход по текущей котировке. Executor не выставляет предварительный limit для этого режима. Это особенно меняет CE Silver Bullet/PO3 и first-touch Seiden. |
| Вход «на close» | Detector задаёт историческое событие, `_confirmation_entry` использует текущую `price_of`. Исторический close/anchor не является гарантированной ценой исполнения. |
| Half TP1 + EMA для каждой continuation | `ema_trail_after_tp1=False`, `_plan` снимает `trail_after_tp1`, кроме `band_exit`. Обычный OTE выходит по целям третями; W/M сохраняет half + trailing. `executor.partial_share=0` отключает дополнительный общий partial, но не собственный half W/M. |
| Break-even после 1R | `be_after_1r=False`. Это отключено явно. |
| Обязательные bias, regime, killzone, premium/discount, HTF POI, perp-led | Большинство этих veto превращаются в shadow-теги через `shadow_vetoes`; тег не запрещает вход. Проверка документации без чтения этой конфигурации даёт неверный результат. |
| Любой `no_*` — shadow | Неверно: важен путь вызова. Например, `no_spring_test` при выполнении теста реально возвращает отказ. Защиты данных, геометрии и пропуска плана тоже остаются. |
| Достаточно убрать veto из shadow-list, чтобы оно блокировало | Не всегда: inline-вызовы `shadow_veto(sig, ...)` для части POI/premium и ORB RVOL/VWAP игнорируют возвращённую причину. Изменение списка в одиночку не превращает их в hard gate. |
| Обязательный order flow | `required_confirmations=()`, `min_confirmations=0`, `require_orderflow_confirm=False`. Механизм `PROMOTED` может подставить требования из калибровки; далее missing confirmations также могут стать shadow. Нельзя считать отсутствие default-требований доказательством, что flow нигде не вычисляется. |
| Каждой модели нужен spot | Реальное обязательное `requires=('spot',)` есть у OTE. Отсутствие такого требования у Turtle соответствует его исходной системе. |
| Watch/zone/trade TTL гарантированно ограничивают удержание | `structural_lifetimes=True` снимает обычные произвольные TTL; остаются структурная отмена и собственные выходы/сессии. SB/PO3 не задают session-end плану: окно detection не ограничивает автоматически последующий entry. У ORB/auction есть собственные окончания сессий. |
| Отключённые стратегии можно исключить из аудита | Нет: PUMP START/TOP разобраны отдельно. Cascade, BB3, RSI2X, OI имеют принудительные shadow-причины и тоже разобраны. Старые BULL A/E в disabled-list не являются отдельными зарегистрированными Strategy. |

Дополнительные реальные ограничения: `sd_score`, отсутствие геометрии/данных, session restrictions конкретных моделей, crowd/notional/execution limits и macro rules в своих путях. Универсального утверждения «все фильтры отключены» в аудите нет. `optimized_profiles=False` исключает текущую подмену всех параметров сохранёнными профилями, но файлы и shadow-калибровки продолжают существовать.

## Формулы и данные: где ошибка, где вариант

- Форма канала Turtle 20/55 и RMA20(TR) верна. Generic ATR в других модулях часто SMA(TR); нельзя объявлять каждый такой ATR неверным только из-за отличия от Wilder. Нужно указывать, какая модель его обещает.
- OHLCV в этом проекте: индекс 5 — quote volume, 6 — taker-buy quote. Это подходит для денежного RVOL, но не автоматически для VWAP/MFI, где цена умножается на объём повторно. Агрегирование не восстанавливает количество актива из turnover с точностью до сделок.
- Закрытый timestamp не означает полную свечу: `resample` допускает неполное покрытие (A04). Для session/TPO важны также разрывы и локальный календарь. ZoneInfo корректно решает DST, но не биржевые праздники.
- Общая геометрия расширяет structural stop за pools/protected swing/pierce и до native ATR floor. Это меняет риск и допустимость каждой стратегии; у source-defined максимума потери нужен отдельный контракт (S07), а RR нужно проверять после окончательной геометрии (S05/S06).
- У SignalBook минутный high/low используется для обычных SL/TP, однако Turtle channel и некоторые динамические выходы проверяют scan price. Восстановление минут после разрыва требует as-of данных, иначе возникает A12. Когда в OHLC баре пересечены SL и TP, stop-first — допущение, а не установленный порядок сделок.
- Количество единиц Turtle и счёт account risk — разные вещи. `turtle_unit_risk=.01` не читается; executor считает 1% риска на весь стоп вместо исходного 1% на N. Лимит 6 направленных units вместо набора 4/6/10/12 основан на предположении корреляции всех монет. Это модификации, даже если защитная политика разумна.
- Исторические replay/ML/placebo не подтверждают live-эквивалентность: A09/A11/A14/A17 описывают доступность labels, несовпадение OI/Cup/band/history и замену выходов. Наличие артефакта модели или зелёных unit-тестов не доказывает доходность стратегии.

## Проверенные общие модули

Реестр файлов и функций с SHA256 — [strategy_manifest.json](strategy_manifest.json). Изучены все 28 файлов `strategies/`: registry/base, detectors, geometry, confirmation, profiles, bias, regime, VSA, indicators, ICT helpers, Turtle и все отдельные playbook. Их чтение связано с `levels.py`, `zones.py`, `signal_book.py`, scanner/loopside, fetcher/replay и executor; отдельный detector не объявлялся полностью проверенной торговой системой.

Общие подтверждения также не приняты на веру:

- `vsa.signs`: low volume действительно ниже обоих предыдущих баров, up/down определяется относительно предыдущего close. Narrow = 0.7×среднего range20, high volume = 2×среднего, положение у края = квартиль окна, для no-demand ещё close-location≤0.6. Это собственные числовые приближения V1. Предыдущие 20 баров и один знак не восстанавливают всю историю профессионального накопления/распределения. `confirm` оставляет последнее событие, в том числе противоположное, а не суммирует независимые подтверждения.
- `confirm.delta` корректно считает taker delta = 2×buy quote − total quote. Это агрессивная сторона сделок, не доказательство намерений всех покупателей/продавцов. OI_EXPECT по семействам — гипотеза проекта, не универсальный закон о росте OI при каждом пробое. Значение `n/a` отличается от False/None, а missing не запрещает вход при отсутствующих данных; это важно для сравнения всех стратегий по одинаковой доступности источников.
- `ict.protected_swing`: собственный 3/3 pivot, окно 96×15m и последующий close за противоположным pivot. `dealing_range` уже использует пару 1h pivot с k=3 и последующие экстремумы; 48h high/low — только fallback. Верхний docstring всё ещё называет 48h окном весь метод. Range position зеркально считается для short и обрезается в [0,1], поэтому значение на краю может также означать цену вне диапазона.
- `ict.fvg_setup/fvg_trigger`, SB и PO3 проверяют знак тела средней свечи, но уже не долю тела ≥50%, которую ещё обещают docstrings. MSS может подтвердиться close средней **или** третьей свечи. Сам gap определяется корректным геометрическим неравенством; оно не измеряет скорость/силу движения. Для старого helper `fvg_trigger` и текущего plan-touch пути различается момент исполнения: нельзя переносить семантику одного helper на все живые входы.
- Bias/regime/profile — вычисленные признаки и статистические политики проекта. Их названия не дают оснований считать собственный EMA slope полным определением Elder tide или ICT bias. Подключение adaptive confirmation по journal требует корректных исходов и исключения смешения версий; A09/A11/A17 мешают использовать нынешние исследовательские результаты как независимое подтверждение всех этих политик.

Не предъявлены как установленные ошибки: включение текущего OI return в среднее, корректная population σ у BB, авторский 0.61 Bulkowski, преднамеренный shadow-status и отсутствие volume gate у Turtle. Не подтверждены как универсальная классика: наша таблица structure/trigger TF, все количественные ICT условия, score Seiden, точная формула Pring и «80%» для нынешних криптоданных. Подробные границы первоисточников — [каталог](STRATEGY_SOURCES.md).
