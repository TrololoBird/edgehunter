этапа 3 и этап 4 - следующими пакетами. Было: черновик. eng-147 закоммичен (758b0ed, 99734bd), НЕ выкачен:

## Исходные факты (журнал, read-only)
- 52 вошедшие сделки eng-135..144: -0.22R, доля плюсовых 38%.
- 9174 уникальных отклонённых / теневых входа: -0.26R (low_rr -0.18, oi_shadow -0.35, flow_entry -0.33,
  reclaim -0.25). Фильтры не инвертированы, но и не дают преимущества: отрезанное и оставшееся одинаково убыточны.
- Среди отклонённых TP1 < 1R: -0.21R, TP1 >= 1R: -0.46R -> минимум TP1 >= 1R не доказан.
- Значимость завышена: одновременные сигналы на одном движении BTC не независимы (нужны кластерные веса).

## Этап 0. Диагностика (только журнал, торговлю не меняет) - eng-148
1. MFE/MAE: за жизнь сделки (вход -> выход), за 10 и 20 баров рабочего ТФ, post-stop MFE за 15 баров после стопа
   (вместо фиксированных 4h). journal.py, колонки mfe_life_r / mae_life_r / mfe_n10_r / mae_n10_r / post_stop_mfe_r.
2. cost_r: фактические издержки сделки в R (taker/maker, спред в момент входа, проскальзывание исполнения).
3. Воронка: для каждой карточки - на каком шаге отвалилась (событие -> план -> зона -> триггер -> R:R -> перебег ->
   рыночный фильтр -> вход); stats.py --funnel по стратегиям.
4. stats.py: веса уникальности 1/c_t (c_t = число одновременных сигналов в 15m-кластере), кластерные ошибки,
   BH-FDR по всем фильтрам; колонки mfe_r / mae_r / trigger_over_atr / cost_r; разрезы по часам UTC, будни/выходные,
   возрасту листинга (<45 / >=90 дней), объёму (<$30M), режиму волатильности (ATR/SMA(ATR,100), Efficiency Ratio).
5. crowd_rank: метка в_топ3 / вне_топ3 для каждого входа (тест Top vs Rest, Spearman IC).
6. Реализм демо: для лимитных входов флаг «цена прошла сквозь уровень >= 1 тик» (иначе исход помечен optimistic_fill).
7. rs_btc: относительная сила к BTC (R_alt - beta*R_BTC за 12h) в момент сигнала.

## Этап 1. Политика демо-счёта - eng-148
1. Лимит одновременных позиций снят на демо (crowd_max, turtle_max_direction_units не ограничивают исполнение;
   turtle_max_units на монету остаётся - это правило Turtles). Ранжирование остаётся в журнале (этап 0.5).
2. executor.demo_off_setups пуст: Bollinger, Market Profile, BREAKOUT, BB1 снова на демо.
3. pump: проверить и закрепить, что доливка 1:1 имеет общий жёсткий стоп на бирже до второго входа и суммарный риск
   обеих частей <= 1R; если нет - доливка только в плюс (после слома структуры вниз), не против движения.

## Этап 2. Откат недоказанных блоков eng-147 - eng-148
1. Фильтры sweep (against_bias / against_trend / no_htf_poi / premium / discount) -> снова теневые (аудит 33).
2. Минимум TP1: глобальный 1R -> теневой; блокирующим остаётся только собственный минимум методики (Seiden 3:1).
   В журнал: rr_tp1 и класс стратегии (mean_reversion / structure / trend) для будущего порога по классу.
3. trigger_overshoot: блок по порогу в ATR -> проверка остаточного R:R в момент триггера (текущая цена -> стоп /
   TP1 >= минимума методики); порог в ATR остаётся только в журнале.
4. market_down: снять с разворотных лонгов (SWEEP LOW, SILVER BULLET LONG, SPRING, FLUSH REVERSAL, demand Seiden,
   VA80 / AUCTION LONG, Bollinger W); для импульсных / пробойных лонгов оставить, плюс теневой вариант
   «BTC 4h close < EMA50 или каскад ликвидаций за 2h» вместо 24h.
5. Остаётся из eng-147: capped_pad, '1R step' только где у методики нет своих целей, swept-уровни, mfe/mae,
   chase_limit, journal-поля.

## Этап 3. Теневые эксперименты (журнал считает виртуальный исход параллельно) - eng-148
1. Вход ICT: лимит на краю FVG / CE и split 50/50 (край + CE, общий стоп) против touch_confirm_close,
   на ОДНОМ множестве карточек после MSS, с учётом карточек, отброшенных low_rr (аудит 13, 34).
2. Стоп в два контура: выход по закрытию 15m/рабочего ТФ телом за уровнем + дальний стоп на бирже (экстремум +
   0.7 ATR); и обычный стоп с буфером в ATR пула (аудит 14).
3. Выход по времени: 6-8 баров триггерного ТФ с MFE < 0.4R -> выход (аудит 14).
4. Повторный вход sweep: второй тест той же зоны после первого касания, если дальняя граница не сломана телом
   (аудит 15).
5. ORB: фильтр NR4 / NR7 / inside day; варианты открытия 00:00 UTC и 13:30 UTC (аудит 6).
6. Wyckoff ST / BUEC: вход на secondary test со стопом за лоу теста, а не за экстремумом spring (аудит 12).
7. Режимы: метка regime (сжатие / тренд / кульминация) для маршрутизации пробоев и разворотов (аудит 23).
8. SMT только BTC/ETH как отдельная метка против текущего SMT альткоина с BTC (аудит 28).

## Этап 4. Изменения логики ядра (каждое - отдельное «да», после 100+ кластерно-независимых сделок этапов 0-3)
1. Bias sweep: без недельного / дневного bias - нет сделки (убрать подмену трендом 1h) (аудит 1).
2. Premium / discount по диапазону ТФ пула (4h / 1d для пулов дня / недели), не по пивотам 1h (аудит 1).
3. Стоп: не переносить за следующий пул; если пул близко (< 1 ATR) - зона ожидания переезжает на него (аудит 2).
4. pierce: глубина прокола в ATR в момент прокола, пулированный перцентиль по группе ликвидности, окно 6 месяцев,
   пересчёт раз в месяц; своя цифра монеты только при N >= 100 (аудит 35).
5. Снятые уровни: при ложном проколе - экстремум прокола как новый пул; при пробое с закрытием 1h/4h - уровень
   S/R flip / breaker вместо удаления (аудит 36).
6. liq_est: только confluence, не цель и не опора; проверка против реальных forceOrder (аудит 8, 37).
7. Выходы по классам: trend (Turtles - канал, без третей; уже так), mean reversion (весь объём на структурной цели,
   Connors SMA5 - уже так), structure (цели только по пулам; '1R step' не сквозь встречную зону) (аудит 3, 31).
8. Минимум TP1 по классу (по кривой P(MFE >= d до стопа) из этапа 0, порог заранее).
9. min_history по стратегиям: Turtles 60 дневок (уже), PMH/PML и недельный bias - не на монетах < 35 / 9 дней;
   решение по возрасту листинга 9 -> 45-60 дней и объёму $10M -> $25-30M по разрезу этапа 0.4 (аудит 24).
10. Trendline: полоса +-0.3 ATR по двум свингам, вход на третьем касании; cup_handle - только 4h / 1d (аудит 16).
11. Ранжирование: если Top vs Rest = шум - заменить на RS к BTC + издержки в R (аудит 40).
12. Риск портфеля для реального счёта (не демо): open heat <= 2.5R по направлению вместо числа позиций (аудит 39).
13. Отключение выходных / ночных часов для пробоев - по разрезу этапа 0.4 (аудит 22).

## Этап 5. Консолидация и исследования (облако, не VPS)
1. 3-4 движка: sweep/spring (разворот), trend pullback (OTE / Seiden), breakout (Turtles / ORB), extreme reversion
   (Connors / pump). Остальное - журнал. Решение по данным этапов 0-4 (аудит 17, 30).
2. Плацебо FVG / OB против сдвинутой зоны той же ширины и простого 50-61.8% отката (аудит 29).
3. liq_est против реальных forceOrder (аудит 37).
4. Правила отключения стратегии: SPRT или 60-100 кластерно-независимых сделок, порог заранее (аудит 38).

## Правила проверки (согласовать ДО запуска)

- Теневой вариант заменяет боевой, только если на >= 100 кластерах: разница E[R] > 0 при p < 0.05 (Welch, кластерные
  ошибки) И E[R] варианта > 0 после cost_r. Порог выбран на первой половине данных, проверен на второй.
- Никаких новых порогов, подобранных по журналу, без out-of-sample проверки на данных после фиксации.
